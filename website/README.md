# Froganize 本地官网 V3（历史设计原型）

> 这里保留的是早期“7 天建议 + 逐项选择”产品方向的静态官网原型，供品牌和
> 设计演进参考。它不再代表当前“一键收好桌面”的产品契约，也不是当前公开
> 下载页。最新行为以仓库根目录的 [`README.md`](../README.md) 为准。

`website/` 是一套独立、纯静态的 Froganize 官网。它复用本地产品的暖奶油色、
钴蓝、黄油黄、珊瑚色和蛙仔品牌形象，并进一步减少卡片、装饰和重复信息。
官网不连接文件系统，也不会执行
评估、归档、撤销或清理操作。

## 最简单的打开方式

1. 在 Finder 中打开 DropNest 项目目录。
2. 进入 `website` 文件夹。
3. 双击 `index.html`。

主页面、开发进度页和隐私页都使用相对路径，所以不启动服务器也可以浏览。

## 使用本机地址预览

在项目根目录运行：

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory website
```

然后打开：

```text
http://127.0.0.1:4173/
```

按 `Control + C` 停止。服务只监听本机回环地址，不会把官网发布到互联网。

## 历史 V3 信息结构

1. Hero：以“给桌面一点整理魔法。”建立品牌记忆，并在 3–5 秒内说清它是什么、怎么工作和为什么安全；
2. Before / Froganize / After：先展示用户最容易理解的整理结果；
3. Inspect → Suggest → Confirm → Undo：全站只保留这一条标准流程，并以四种
   SVG 蛙仔姿态连接绘本故事与真实产品状态；
4. 真实界面：桌面与手机分别使用可读的真实产品截图；
5. Local First：讲清普通桌面整理不上传内容；只有用户明确开启截图智能后，匹配的系统截图才会发送给所选 Provider；所有移动仍需确认、不覆盖且可撤销；
6. 蛙仔绘本：四幕故事成为自然经过的连续章节，插图以渐变和留白融入页面背景，不再作为独立照片卡片或“听故事”入口；
7. Developer Preview：提供真实的开发进度和隐私出口，不伪造下载或 GitHub 链接。

页头和首屏都提供“下载”入口。在可公开安装包尚未就绪时，它们统一跳到
页面内的真实发布状态区，说明已完成与待完成事项；只有真实、稳定的公开
下载地址确认后，才会替换为直接下载链接。

## 文件说明

- `index.html`：官网首页；
- `changelog.html`：面向用户的开发进度；
- `privacy.html`：中文隐私与文件安全承诺；
- `styles.css`：共享设计系统与响应式样式；
- `robots.txt`：允许抓取，但在域名确认前不声明无效 Sitemap；
- `assets/social-preview.png`：已准备好的 1280 × 640 社交预览图；
- `assets/dashboard-ui*.png`：桌面与移动端真实界面素材。
- `assets/froganize-{idle,organizing,calendar,success}.svg`：透明背景的产品内
  矢量蛙仔，分别用于基础、整理、日历和完成状态。

## 隐私与性能

官网没有外部字体、分析脚本、Cookie、遥测或网络素材。产品截图只使用合成演示
文件，不含真实桌面内容。页头使用 128px 吉祥物缩略图，首屏图设置高优先级，
非首屏图片延迟解码与加载；移动端产品图不会把桌面截图强行缩小。

## 发布前仍需补齐

域名、GitHub 仓库和真实下载地址目前都没有确认，因此页面有意不加入伪造链接。
正式发布前应完成：

- 确认域名后加入 canonical 与 `og:url`；
- 将 `assets/social-preview.png` 的绝对地址写入 `og:image`；
- 用真实域名生成 `sitemap.xml`，并在 `robots.txt` 中声明；
- macOS 安装包签名、公证并在另一台 Mac 上验证；
- 最后再开放唯一、稳定的下载按钮和 GitHub 地址。
